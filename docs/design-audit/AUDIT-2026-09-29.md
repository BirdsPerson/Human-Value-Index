# HVI design audit: every screen except the city, 2026-09-29

Follow-up to the 2026-09-26 audit (`AUDIT.md`, fixed in the `5a7478c` design pass). Scope:
logon/boot, menu, the written survey and its result, voice and typed intake, MY FILE
(file, movement, directives and vouches, appeals, case file and email), the Public Figure
Index and ANALYTICS, the cube, the holding pen's chrome (referral bar, pick list, queue,
registry, subject card), and the loading, empty and error states. The city (`src/city/*`)
and the sprite pipeline were out of scope.

**Method.** A Playwright harness ran 24 states at 390x844 (iPhone emulation, touch, DPR 2)
and 1440x900, against the live site and a local dev server. Personal-file APIs were mocked
so that every state rendered: a file on record with five history entries, a held
directive, a vouch, a signed-in email, a namesake pick list, and failures. Public GETs
(the pen, the atlas) went to production. Each screenshot got a probe for:

- horizontal scroll (`scrollWidth` against `innerWidth`)
- tap targets under 44px
- inputs under 16px
- body-text contrast against the nearest opaque background
- console errors

Live and local measured the same before the pass. After the pass, live measured the same
as local again.

## What the 2026-09-26 fixes still hold

These still pass on every route:

- No horizontal scroll at 390.
- No input under 16px.
- No console errors.
- No tap target under 44px outside the analytics marks, which are now fixed.

The command bar, sticky header, once-per-device boot, TAP TO OPERATE, compact index rows
and the file-first result all hold. What was left is hierarchy and polish, not structure.

## Still open (a later pass)

1. **The analytics palette.** TRUSTED RESERVE is blue (`#3c8fd6`), outside the three
   hues. It was validated for colour-blind separation, so swapping it needs a new check,
   not a guess. Twelve charts also run to about 14 phone screens: the four most useful
   could go first, with the rest behind one disclosure.
2. **Pen help text.** Three paragraphs of instructions sit under the canvas on every
   visit. Show them once per device, as the boot does, then collapse them to one line.
3. **The survey progress bar.** Eighty `░` characters read as a grey hatched band at 0%.
   A bar that fills the width in real characters needs the width measured. I tried 40
   characters: it fell short of the width and read worse, so I reverted it.
4. **Tabs on non-routes.** The survey, its result and the index are phases, not routes,
   so the bar shows MENU as current on all three. The index deserves a route
   (`#index`) and, arguably, a tab.
5. **Frame depth on the card.** SUBJECT FILE (box) contains VALUE INDEX (double) and THE
   CUBE (box). That is within the two-deep rule, but the card could drop its outer box
   now that the name heads it.
6. **The live interview's first line.** The status row's blinking `●` leaves a gap when it
   blinks off, so the row looks indented half the time.
